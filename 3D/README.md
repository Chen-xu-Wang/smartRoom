# 筑维AI · 小区 3D 数字孪生

浏览器里运行的小区数字孪生：在 3D 场景中复刻"主动感知 → 住户提醒 → 工单 → 派单 → 维修"的完整闭环，
支持**物业 / 业主 / 住宅 / 维修人员**四个视角切换，问题可一键定位到具体部位，并与 2D 户型平面图联动。

> 全部数据为模拟数据（`SIMULATED`），页面常驻"演示数据"角标。设计方案文档不随仓库发布。

## 两种运行方式

**① 内嵌在现有前端里（主用法）**：3D 是现有前端的一个页面，路由 `/twin`，
和"物业管理""房屋管理"一样在当前界面内切换，顶部导航与页脚都是现有前端的。

```bash
npm --prefix frontend install   # 已包含 three、camera-controls
npm --prefix frontend run dev
```

打开 http://localhost:5173 ，登录后点顶部导航的「3D 数字孪生」。

**② 独立运行（调试 3D 本身时更快）**：

```bash
npm --prefix 3D install
npm --prefix 3D run dev
```

打开 http://localhost:5174 ，用 3D 自己的登录框登录。**两种方式都需要后端（8000 端口，`.claude/launch.json` 里的 `backend`）**：
小区模型和演示事件含全部住户档案，由后端按登录账号裁剪后下发，不再放在前端 public 目录。

顶部"演示样例 / 联机数据"切换的是事件来源：演示样例来自 `/api/twin/demo-events`，
联机数据的事件、提醒、建单、复查走现有的 `/api/sensing/*` 接口，两者都按账号过滤。

重新导出数据（改了 `sim_building.json` 或演示事件后）：

```bash
python 3D/scripts/build_twin_data.py
```

## 现有系统里的入口

| 位置 | 入口 | 带过去的上下文 |
| --- | --- | --- |
| 顶部导航（**登录后才显示**） | 3D 数字孪生 | 按当前登录角色打开对应视角 |
| 房屋档案页 | 在 3D 中查看本户 | 档案透视视角 + 该户 |
| 工单详情页 | 在 3D 中定位故障部位 | 维修视角 + 联机数据 + 触发事件 |
| 物业后台「主动感知」每条事件 | 3D 定位 | 物业视角 + 联机数据 + 该事件 |

都是页面内跳转（`router.push('/twin?...')`），不开新标签页。上下文通过路由 query 传递：
`role`（property/owner/archive/repairer）、`house`、`event`、`code`、`floor`、`building`、`theme`、`live=1`。

内嵌时登录用户天然一致（同一个 `stores/auth.js`），视角与可见范围按账号角色锁定（见下方「权限」）。
入口参数都要过权限检查：`role` 不在账号允许范围内时改用默认视角，`house`/`event`/`code` 越权时提示并忽略。
登录后后端签发访问令牌，所有接口都带 `Authorization: Bearer <token>`，令牌失效时回到登录。
独立运行（5174）与控制台（5173）端口不同、登录态不互通，需要分别登录；令牌不通过 URL 传递。

**界面一致**：3D 复用现有前端的 `styles/main.css`（主色、字号、圆角、阴影、字体），
内嵌时隐藏 3D 自己的品牌栏、登录入口和页脚，只保留视角切换、一键定位、数据模式与昼夜切换。
3D 的样式分成两份：`styles.css`（只含 `.twin-root` 内部的样式，内嵌时也加载）和
`standalone.css`（整页铺满、禁止滚动、3D 自己的页脚，只有独立运行才加载），
这样内嵌时不会影响前端其它页面的滚动与布局。

## 四个视角

| 视角 | 能做什么 |
| --- | --- |
| **物业** | 全小区运行看板、待处理问题列表、为事件建单、MiC 批次热力、楼栋切换 |
| **业主** | 只能进入自己家（隐私保护），查看健康提醒、自检步骤、一键报修、设备状态 |
| **住宅** | 一房一码档案透视：结构 X 光、给水/排水/立管/电气回路/传感器图层、批次与供水分区着色、构件档案卡 |
| **维修人员** | 我的任务、作业安全提示、作业前隔离点、建议携带材料、从小区大门到故障部位的导航路线 |

## 权限

规则集中在 `src/data/access.js`，引擎（`Engine.setScope`）和界面两层都做拦截：

| 登录角色 | 可用视角 | 可进入的住户 |
| --- | --- | --- |
| 物业 / 管理员 | 物业、住宅、维修人员（只读） | 全部 |
| 居民（业主） | 业主、住宅 | 仅名下住宅 |
| 维修人员 | 维修人员、住宅 | 仅自己工单涉及的住户 |

- 受限账号可以看小区与楼栋外观，不能浏览整层（点楼层会直接进入本层自己可进入的户），没有批次/分区着色与整栋统计。
- 业主只看到自家信标；邻居家的问题影响到本户时，只显示给本户的提醒和本户受影响部位，不显示原始标题、证据、邻居户号与监测曲线。
- 维修人员只看派给自己的工单（不再显示待派单兜底），不能切换维修人员身份。
- 业主房屋来自后端 `user_house` 绑定（登录接口返回 `house_ids`，物业在「人员管理」里维护），不信任登录时手填或地址栏里的房号。
- 后端按同样规则裁剪数据（`backend/app/security.py`、`services/event_access.py`、`api/twin.py`）：
  - `/api/twin/building`：无权访问的住户只返回户型外壳（户号、楼层、户位、户型），设备、传感器、管线、登记人数等为空；
  - 邻居事件只返回发给本户的提醒，事件号换成不透明别名（原事件号含发生户房号），不含定位候选、证据、控制动作、监测数据；
  - 维修人员只拿到自己工单的事件，提醒只保留给物业的。
- 前端的拦截负责交互体验（提示、不显示按钮），越权请求由后端返回 403。

## 代码结构

```
3D/
├── scripts/build_twin_data.py   从 data/processed 导出 backend/app/data/twin/*.json
（数据放在后端，由 /api/twin/* 按账号裁剪后下发，两种运行方式共用：
   building.json 108 户拓扑、管线、回路、传感器、设备档案；
   demo_events.json 13 类 P0 事件 + 决策 + 演示工单）
└── src/
    ├── TwinRoot.vue              3D 主体组件（内嵌与独立共用，embedded 属性区分）
    ├── App.vue / main.js         独立运行入口
    ├── data/     layouts(户型几何) · site(小区总图) · resolver(编码→坐标) · events · loader
    ├── engine/   Engine(层级/剖切/拾取) · buildSite · buildBuilding · buildUnit · Highlighter · materials · geo
    ├── ui/       TopBar · NavBar · 四个视角面板 · DetailPanel · FloorPlan2D · LoginDialog
    └── stores/   twin.js
```

**复用现有前端**（`@app` → `../frontend/src`）：接口封装 `api/index.js`、登录状态 `stores/auth.js`、
图表组件 `components/SensingChart.vue`。3D 场景、2D 平面图、镜头与高亮是新增部分。
现有前端侧新增 `views/Twin3D.vue`（页面壳）、`/twin` 路由、`utils/twin.js` 与四处入口，
以及 vite 里的 `@twin` / `@app` 别名；未改动原有业务逻辑。

## 说明与边界

- 户型几何是**示意设计**：档案只提供管线位置的文字描述，档案原文在构件卡里原样显示。
- 只有 **1栋**接入模拟数据；2–6栋复用 1栋的结构，可以进入查看，但不显示告警与工单，页面提示"暂未接入"。
- 事件来源在详情里标注：`检测样例`（算法输出）/ `契约样例` / `演示样例`（人工构造）/ `联机数据`。
- 联机模式下事件、工单都来自后端：工单只取 `source = AUTO_SENSOR` 的主动感知工单；尚未派单时维修视角显示待派单工单。
- 性能：小区全景约 360 次绘制调用、70 万三角形；进入楼层时会有一次着色器编译的短暂卡顿。
