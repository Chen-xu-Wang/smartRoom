# 百炼调试样例包

> 版本：v0.1（2026-09-15，任务 1.1 的手工样例）。任务 1.13 会扩充到 20–30 个事件样例，并补充知识库素材
> 契约说明：`../contracts/README.md`
> 所有样例均为手工编写的**模拟数据**，数值之间已做一致性核对（`python data/scripts/validate_contracts.py` 全部通过）

## 一、目录

```
bailian_kit/
├── events/          契约① 事件输入（5 个）       → 百炼应用① 事件解读
├── monthly/         契约③ 住户月报输入（1 个）   → 百炼应用② 月度报告
├── batch_brief/     契约③ 批次简报输入（1 个）   → 百炼应用② 月度报告
├── qa/              契约④ 问答上下文（1 个）     → 百炼应用③ 水电问答（P1）
├── expected/        以上 8 个输入的参考输出（契约②③④）
├── prompts/         3 个应用的系统提示词（已嵌入示例，直接复制到百炼大模型节点）
└── runs/            call_bailian.py 批量调用的输出（运行后生成）
```

> 百炼的详细操作步骤见《百炼操作指南》文档（不随仓库发布）。
> 提示词中嵌入的示例：应用① 为 01、03（`knowledge_refs` 只保留现有手册章节）；应用② 为住户月报 01；应用③ 为问答 01。**这些样例只用于回归检查，检验效果要看没有嵌入提示词的样例。**

## 三、在百炼中怎么用

1. **搭建阶段**：把 `events/` 中的 JSON 整段复制，作为开始节点 `event_json` 参数的测试输入。
2. **写提示词**：从 `expected/` 中挑 1–2 个作为 few-shot 示例，建议选 01（常规）和 03（紧急电气），两者差异最大。其余样例留作测试，不要放进提示词，否则无法检验泛化效果。
3. **看结果**：百炼输出**不要求逐字一致**，要求的是：
   - 能通过 Schema 校验；
   - 满足 `contracts/README.md` 第五节的决策规则；
   - 文案中的数字都能在输入中找到出处。
4. **自动校验**：把百炼输出存成文件后运行：

```bash
python data/scripts/validate_contracts.py --contract event_decision --file 百炼输出.json --event data/processed/bailian_kit/events/03_terminal_overheat_1302_kitchen_circuit.json
```

## 四、提示词要点（应用①，供参考）

1. 角色：住宅主动运维助手。只能基于 `event_json` 和知识库检索结果作答，不得编造数值、位置和设备。
2. 输出：只输出一个符合契约② 的 JSON 对象，不输出任何其它文字。
3. 按第二节"走哪条分支"和契约 README 第五节的决策规则确定 priority、提醒对象和建单方式。
4. 住户、家属、邻户文案：通俗、先说结论、给出可能性百分比；不出现专业术语和具体作息时间；自检类提醒附免责提示。
5. 维修工单 `ai_summary`：写清证据、定位候选及其置信度、处置思路和建议材料。
6. 作业安全提示：电气类必须含验电、断电挂牌；有积水时必须提示插座回路风险。
7. 已在 `control_actions_taken` 中执行过的动作不要再建议。
8. 批次事件：显著（p<0.05）与不显著要分开表述，不显著的只能说"偏高、需确认"。
