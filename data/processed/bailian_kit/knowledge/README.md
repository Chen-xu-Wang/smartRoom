## 三、知识分类结构

```
知识库「筑维AI-住宅运维知识库」
├── 给排水维修手册     # 手册 = 一个 md 文件 = 一个一级标题
│   ├── 厨房水槽持续漏水   # 章节 = 二级标题 ##，也是检索与引用的最小单位
│   ├── 卫生间排水缓慢
│   └── 卫生间花洒出水异常
├── 电气维修手册
├── 空调维修手册
├── 门窗与综合维修手册
└── 主动运维补充
    ├── 爆管与水浸处置
    ├── 端子发热处置
    ├── 批次质量巡检
    └── 独居守护分级响应
```

每个章节内部固定用这几个三级小节，便于按长度切分后仍能保留语义：

`### 常见原因` / `### 关键判断依据` / `### 处置流程` / `### 建议工种` / `### 紧急等级` / `### 安全提示` / `### 住户沟通要点`

## 四、引用约定（knowledge_refs）

事件决策输出的 `knowledge_refs` 格式固定为 **"手册名-章节名"**，即"一级标题-二级标题"，例如：

- `给排水维修手册-卫生间花洒出水异常`
- `电气维修手册-配电箱跳闸`
- `主动运维补充-端子发热处置`
- `主动运维补充-独居守护分级响应`

提示词要求模型只能引用检索结果中真实出现的章节名；检索为空时输出 `[]`。这样评审可以逐条核对"AI 说自己参考了什么"是否真实存在。

## 五、主要内容示例

`主动运维补充-端子发热处置` 节选：

> **断路器出线端子松动或氧化**（最常见）：接触电阻增大，同样电流下温升明显高于正常
> - 判断方法：单位电流平方温升（℃/A²）随时间持续升高，而电流并未增大
> - 处理方式：验电断电后检查端子烧蚀情况，清洁后按规定力矩紧固；烧蚀严重的更换断路器
>
> 关键判断依据：电流未超额定 + 温升持续恶化 → 端子接触不良；电流接近额定 + 温升同步上升 → 过载
>
> 安全提示：作业前验电…断电后挂牌上锁…绝缘层碳化的导线必须更换

这一节直接支撑样例 03 的输出：工单 `worker_safety_notice` 里的"验电""挂牌上锁"、材料里的"扭力螺丝刀/红外测温仪"，以及"电流 11.8A 未超额定 16A，因此排除过载"这一推理。

`主动运维补充-独居守护分级响应` 里的分级表则直接决定样例 05 的 `escalation`（20 分钟后升 3 级）和"不建工单"，以及隐私要求（不得写出具体作息时间）。

## 六、百炼侧的建库参数（与 `../BUILD_GUIDE.md` 第二节一致）

| 项 | 取值 | 理由 |
| --- | --- | --- |
| 知识库类型 | 文档搜索（非结构化） | 手册是 markdown 文本 |
| 切分方式 | 按标题层级切分；无标题层级时按长度 500 字、重叠 100 字 | 章节内部小节较短，按标题切能保住"原因—判断—处置"的完整性 |
| 向量模型 | 平台默认 embedding 模型（中文多语种） | 手册为中文短段落 |
| 召回数量 | 5 | 一次事件一般只命中 1-2 个章节，5 条足够且不挤占上下文 |
| 相似度阈值 | 0.2 | 阈值过高会导致"爆管"这类新词召回为空 |
| Rerank | 开启 | 手册里多个章节都含"漏水""跳闸"，靠 rerank 拉开差距 |

> 知识库目前只在**华北2（北京）**地域可用，API 调用的 base_url 也要用北京地域，否则应用调用会报找不到知识库。
