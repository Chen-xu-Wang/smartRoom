## 二、运行

```bash
python data/scripts/build_building.py                 # 1.2 楼栋拓扑 + 画像分配 + 自检
python data/scripts/run_behavior.py --dataset dev     # 1.4 行为预览 + 自检（test 同理）
python -m unittest discover -s data/scripts/tests -v  # 单元测试（15 项）
python data/scripts/validate_contracts.py             # 契约样例校验
```

依赖：`numpy`、`pandas`、`scipy`、`PyYAML`（本机均已安装）。

同一种子重复运行，结果逐字节一致。所有随机数由 (数据集种子, 户号, 用途) 决定，与住户遍历顺序无关。

## 三、楼栋拓扑（1.2）

### 3.1 总体

| 项 | 设定 | 依据 |
| --- | --- | --- |
| 规模 | 1栋1单元，18 层 × 6 户 = 108 户 | 工作方案决策 |
| 户型 | 户位 01/02 → T89（三室两厅一卫 89.5㎡），03/04 → T75（两室两厅一卫 75㎡），05/06 → T65（两室一厅一卫 65㎡） | 户位 02/03/05 分别对齐 1302/503/805 的档案 |
| MiC 批次 | A = 1–6 层，B = 7–12 层，C = 13–18 层；生产与交付日期取自 503/805/1302 档案 | 档案 |
| 供水分区 | 低区 1–4 层（市政直供）；中区 5–11 层、高区 12–18 层（变频泵）；第 5、12 层加装支管减压阀 | 每区最低用水点静压 ≤ 0.45 MPa，入户静压 0.20–0.35 MPa（GB 50015） |
| 排水立管 | 每个户位一根，`ST01`–`ST06` | 简化假设（见第六节） |
| 电气相别 | L1 = 户位 01/04，L2 = 02/05，L3 = 03/06 | 三相均衡 |
| 热水 | 所有户型均为储水式电热水器；T89 经热水管同时供厨房和卫生间，T75/T65 只供卫生间 | 1302 档案有厨房热水管，805/503 没有 |

批次与分区刻意不完全重合（A 批次跨低区和中区，B 批次跨中区和高区），这样批次对比时可以按分区分层，避免把水压差异误判为批次质量问题。

### 3.2 档案住户

1302（14 件）、805（8 件）、503（7 件）的档案设备**全部保留原编码、型号和安装日期**。户型需要、但档案里没有的部件，按同一编码规则补充，并标 `in_archive: false`。例如 805 补充了 `EQ-805-B-02` 花洒、`EQ-805-K-03` 连接软管。

契约样例引用的全部编码都已在楼栋文件中生成：`WS-1302-B-SH`、`WS-805-K-HS`、`WS-805-IN-MV`、`CB-1302-KT`、`SN-805-K-WL01`、`SPK-503-L-01` 等。

### 3.3 每户对象

| 字段 | 内容 |
| --- | --- |
| `supply_network` | 给水有向无环图：`IN-MT` 水表 → `IN-MV` 电动总阀 → [`IN-PRV` 减压阀] → `IN-FLT` 过滤器 → `IN-MAIN` → 厨房/卫生间/阳台支路 → 角阀、软管、混水阀 → 器具；热水器 `WH-FLT` → `WH` → 热水支路。混水器具有冷、热两个上游节点；`loss_param` 指向参数库中的压降参数 |
| `drain_network` | 排水点（地漏、存水弯、马桶排水口）→ 横支管 → 立管接入点 `ST0n-F{层}`；`receives` 为汇入的器具；`tau_param` 指向退水时间常数 |
| `circuits` | 照明、普通插座、厨房插座、卫生间、热水器、空调回路：额定电流、剩余电流保护动作值，均带端子测温和剩余电流测量 |
| `sensors` | 按"方案 3"布点：入户流量与压力（过滤器前后）、4–5 路支路流量、器具末端压力、热水器进出水温度、3–4 个排水水位、3 个水浸、客厅与卫生间雷达、空调房间温湿度；关怀登记住户另有卧室雷达和智能音箱 |
| `devices` | 扩展档案设备清单，含 `segment_code` / `circuit_code` 关联 |

### 3.4 画像分配

| 户型 | 双职工带孩子 | 年轻情侣 | 独居老人 | 长期出差 | 空置 |
| --- | --- | --- | --- | --- | --- |
| T89 | 30 | 3 | 0 | 0 | 3 |
| T75 | 4 | 12 | 8 | 6 | 6 |
| T65 | 0 | 15 | 8 | 6 | 7 |

固定画像与契约样例一致：1302 为三口之家，805 为双职工（白天无人），503 为独居老人（关怀登记）。画像分配在 dev、test 之间共用（它是楼栋的一部分）；每户的具体习惯在两个数据集中分别独立抽取。

### 4.3 与契约样例对齐的取值

- 厨房插座回路额定电流取 **16 A**，与样例 03 一致。大功率电器叠加时可能跳闸，这是真实现象，由 1.6 模拟。

## 五、行为模型（1.4）

### 5.1 三层结构

| 层 | 函数 | 随机流 | 产出 |

| 住户习惯 | `draw_profiles` | (种子, 户号, `habits`) | 每人：起床/入睡/出门/回家时刻的个人均值与逐日波动、淋浴次数与时长、龙头与花洒习惯开度、淋浴水温、吹风机概率等。每户：热水器模式与设定温度、空调开机阈值与设定温度、洗衣频率与时段偏好、常开待机功率、冰箱日耗电 |

| --- | --- | --- | --- | --- | --- |

### 5.4 行为层自带的天然干扰（检测算法必须扛住）

| 干扰 | 行为层表现 | 考验的检测能力 |
| --- | --- | --- |
| 住户很少把龙头开到最大 | 开度均值 0.55–0.60，全开概率 12% | 进水堵塞检测须用出水能力上限（P90），不能用平均值 |
| 多器具同时用水 | 家庭晚间淋浴、洗碗、洗衣重叠 | 用水事件分解、N3 |
| 访客 | 周末午后如厕、洗手激增 | 用水异常误报、N5 |
| 暑期出游、出差 | 连续多日零用水、零活动 | 暗漏最小夜间流量、关怀误报、N4 |
| 独居老人午睡 | 约 75% 的日子卧室长时间静止 | 关怀"长时间静止"误报 |
| 工作日与周末作息差异 | 周末起床晚约 1.5 h | 基线须区分工作日与周末 |
| 暑假 | 7 月 4 日起孩子白天在家 | 基线漂移 |

## 六、已知简化与局限

1. **排水立管**：每个户位只设一根，厨房、卫生间、阳台排水都接入。实际工程中厨房、阳台常为独立的废水立管。
2. **灶具**：按燃气灶处理，不计电耗。
3. **行为层用水估算**：自检中的用水量是按入户静压和水效流量折算的**估算值**，精确水量由 1.5 的水力模型计算。两者量级应一致，1.8 自检会复核。
4. **季节**：只模拟夏季 90 天。防冻、冬季热水能耗属于 P2，需要时再补冬季窗口。
5. **外出计划与窗口长度有关**：改变模拟起止日期会改变出游、出差安排。可复现性以固定窗口为前提。
6. **调参记录**：
   - **dev 数据集**：首轮自检发现用水偏高（家庭 248 L/人·日），据此下调了洗手频率、刷牙时开度、洗碗次数与时长、淋浴开度和时长，并按家庭人数缩放做饭用水。每次调整都记录在参数库的取值中。
   - **test 数据集**：只用来复核，没有据此调参。复核时发现 1 处过零点入睡产生零长度区间的边界缺陷，已作为代码缺陷修复。
